Представляем **Nanocl 0.17**! Версия повышает продуктивность разработчиков и развивает сетевые возможности: новые и улучшенные команды CLI, распределённая координация в демоне и экспериментальная поддержка HTTP/3 в `ncproxy`. Создавать Statefile стало удобнее благодаря улучшенному разбору аргументов, метаданным и встроенному выводу руководства.

{/* truncate */}

## Главное в Nanocl 0.17 [#highlights-of-nanocl-017]

- Улучшения CLI: `nanocl logs` для нескольких целей, новая `nanocl stats`, команды Statefile `state man` и `state render`, а также улучшенный разбор аргументов.
- Надёжность платформы: распределённый мьютекс в `nanocld` предотвращает повторение задач на разных узлах; сертификаты БД безопасно синхронизируются через секреты.
- Современный прокси: `ncproxy` настраивает HSTS через правила и экспериментально поддерживает HTTP/3 с настраиваемыми параметрами.

## Изменения компонентов [#component-changes]

### nanocl 0.17.0 [#nanocl-0170]
- Добавлено:
  - `nanocl stats` для статистики нескольких процессов по имени (спасибо [n0tank3sh](https://github.com/n0tank3sh)).
  - `nanocl state man` для руководства Statefile.
  - `nanocl state render` для формирования Statefile с текущими переменными контекста.
  - `nanocl logs` теперь принимает несколько имён.
  - Улучшен разбор аргументов Statefile: обязательность, несколько значений и описания.
  - Метаданные Statefile для более подробного руководства.
  - `nanocl secret patch` обновляет секрет без удаления.

### nanocld 0.17.0 [#nanocld-0170]
- Добавлено:
  - Конечная точка `GET /process/{name}/stats` для статистики процесса по имени, автор [n0tank3sh](https://github.com/n0tank3sh).
  - Сохранение сертификата БД в секрет для обмена и синхронизации между узлами.
  - Распределённый мьютекс предотвращает одновременное выполнение одной задачи разными узлами.

### ncproxy 0.14.0 [#ncproxy-0140]
- Добавлено:
  - Настройка HSTS через правило прокси, автор [n0tank3sh](https://github.com/n0tank3sh).
  - Экспериментальная поддержка HTTP/3.

## Руководства Statefile [#statefile-manuals]

Теперь руководство Statefile можно просматривать прямо в терминале. Новая команда `nanocl state man` выводит подробное руководство с метаданными, описаниями аргументов и примерами.

![Руководство Statefile](/img/statefile-man.png)

Пример Statefile с подробным руководством для команды `nanocl state man`:

```yaml
ApiVersion: v0.17

Metadata:
  Name: Nginx with Certbot SSL
  Tags:
  - cargo
  - nginx
  - certbot
  - ssl
  - proxy
  About: Example of an Nginx cargo with Certbot managed SSL certificates.
  LongAbout: |
    This example demonstrates how to create an Nginx cargo with SSL certificates
    managed by Certbot. The cargo is configured to always pull the latest Nginx image
    and automatically handle SSL certificate issuance and renewal.

Args:
- Name: name
  Kind: String
  Required: true
  Description: Name of the cargo to create.
- Name: testtt
  Kind: String
  Description: sample test
- Name: multiple
  Kind: String
  Multiple: true
  Description: sample multiple
- Name: boolean
  Kind: Boolean
  Description: sample boolean

Namespace: cargo-example

Cargoes:
- Name: ${{ Args.name }}
  ImagePullPolicy: Always
  Metadata:
    Certbot: managed
  Container:
    Image: nginx:latest
```

<Callout type="info">

Все доступные метаданные и параметры аргументов описаны в документации [Statefile][statefile-doc].

</Callout>
