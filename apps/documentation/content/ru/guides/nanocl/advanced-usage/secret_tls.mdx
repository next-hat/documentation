# Секреты TLS

Для добавления SSL-сертификата создайте секрет.<br/>

Nanocl хранит сертификат TLS, закрытый ключ, сертификат CA и параметры DH как содержимое PEM в CockroachDB. `ncproxy` записывает их в рабочий каталог только когда Nginx нужны файлы.

## Ручная настройка [#manual-setup]

<Callout type="default" emoji="💡">

Секреты можно создавать прямо в `Statefile` развёртывания!<br/>
Но мы рекомендуем `Statefile` вида `Secret` и отдельное управление ими.

</Callout>

Пример `Statefile`:

<StatefileBlock example="advanced/secret-tls" />

Можно загрузить локальные PEM-файлы через CLI. Nanocl читает файлы до создания секрета, поэтому CockroachDB хранит содержимое, а не локальные пути:

<CodeBlock className="language-sh">
{`nanocl secret create tls tls.secret \\
  --certificate-path ./server.crt \\
  --certificate-key-path ./server.key \\
  --certificate-client-path ./ca.crt
`}
</CodeBlock>

<Callout type="info">

При первом запуске после обновления до Nanocl 0.18 `nanocld` преобразует старый секрет TLS базы данных из читаемых путей файловой системы в содержимое PEM. Сохраните доступ к старым файлам для этого запуска. Если файлы будут недоступны, обновите секрет до содержимого PEM, пока демон 0.17 и файлы ещё доступны, либо восстановите файлы перед запуском 0.18.

</Callout>

## Автоматическая настройка с Let's Encrypt [#automatic-with-lets-encrypt]

Используйте [certbot](https://certbot.eff.org/) для сертификата своего домена.<br/>
Мы подготовили универсальный `Statefile`, который выполняет задание и создаёт нужный `secret`.<br/>
Секрет получит имя `cert.{domain_name}`.<br/>

<CodeBlock className="language-sh">
{`nanocl state apply -fs nr.next-hat.com/v${nanoclMajorVersion}/certbot -- --email your@email.com --domain deploy-example.com
`}
</CodeBlock>

После завершения команды SSL уже будет включён, но нужно обновить `ProxyRule`.<br/>
