# TLS Secret

添加 SSL 证书需要创建 Secret。<br/>

Nanocl 在 CockroachDB 中以 PEM 内容保存 TLS 证书、私钥、证书颁发机构和 DH 参数。只有 Nginx 需要文件时，`ncproxy` 才将这些值写入运行时目录。

## 手动配置 [#manual-setup]

<Callout type="default" emoji="💡">

可以直接在部署 `Statefile` 中创建 Secret。<br/>
但我们建议使用 `Secret` 类型的 Statefile，单独管理它们。

</Callout>

下面是实现这一方式的 `Statefile` 示例：

<StatefileBlock example="advanced/secret-tls" />

也可以通过 CLI 加载本地 PEM 文件。Nanocl 在创建 Secret 前读取文件，因此 CockroachDB 保存文件内容，而不是本地路径：

<CodeBlock className="language-sh">
{`nanocl secret create tls tls.secret \\
  --certificate-path ./server.crt \\
  --certificate-key-path ./server.key \\
  --certificate-client-path ./ca.crt
`}
</CodeBlock>

<Callout type="info">

升级到 Nanocl 0.18 后首次启动时，`nanocld` 将旧数据库 TLS Secret 中可读取的文件路径转换为 PEM 内容。首次启动时保持旧文件可用。如果文件将不可用，请在 0.17 守护进程和文件仍可访问时，将 Secret 更新为 PEM 内容，或在启动 0.18 前恢复文件。

</Callout>

## 使用 Let's Encrypt 自动配置 [#automatic-with-lets-encrypt]

可以用 [Certbot](https://certbot.eff.org/) 为域名生成证书。<br/>
我们提供了通用 `Statefile`，自动执行任务并创建合适的 `Secret`。<br/>
Secret 名称为 `cert.{domain_name}`。<br/>

<CodeBlock className="language-sh">
{`nanocl state apply -fs nr.next-hat.com/v${nanoclMajorVersion}/certbot -- --email your@email.com --domain deploy-example.com
`}
</CodeBlock>

命令完成后 SSL 已启用，但还需要更新 `ProxyRule`。<br/>
