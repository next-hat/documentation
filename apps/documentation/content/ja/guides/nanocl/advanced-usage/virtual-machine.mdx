# 仮想マシンを作成する

`Nanocl` で、[cloud-init][cloud-init] に対応する仮想マシンを素早く起動できます。<br/>
多くの Linux クラウドイメージには標準で含まれており、仮想マシン内のネットワーク、ユーザー、SSH キーを設定できます。

## デフォルトの仮想マシンランタイムをインストールする [#install-the-default-vm-runtime]

ネットワークの扱いを簡単にするため、Nanocl はデフォルトのランタイムイメージ [nanocl-qemu][nanocl-qemu] を使い、コンテナ内で仮想マシンを起動します。<br/>


## 初期化コンテナで Ubuntu をダウンロードして仮想マシンのディスクを作成する [#download-ubuntu-and-create-a-vm-disk-with-an-init-container]

Nanocl は仮想マシンのイメージパスを直接使います。Nanocl 0.18 では、仮想マシンの `InitContainer` で Ubuntu のクラウドイメージをダウンロードし、QEMU ランタイムコンテナが起動する前に `qemu-img` で独立した qcow2 ディスクを作成します。これにより、ホスト側で手動の準備をせずに、ダウンロードとディスクの準備を仮想マシンのライフサイクルに含められます。

次の Statefile は、`/var/lib/nanocl/vm` に `web-01` のディスクを作成します。初期化コンテナは Ubuntu Server 24.04 をダウンロードし、`qemu-img convert` で書き込み可能な `web-01.qcow2` のコピーを作成します。仮想マシンのランタイムは、このコマンドがステータス `0` で終了してから起動します。

```yaml
ApiVersion: v0.18
VirtualMachines:
- Name: web-01
  Image: /var/lib/nanocl/vm/web-01.qcow2
  InitContainer:
    # Omit Image to use Nanocl's default nanocl-qemu runtime image.
    Entrypoint: ["sh", "-ec"]
    Cmd:
    - |
      mkdir -p /images
      test ! -e /images/web-01.qcow2 || {
        echo "VM disk already exists: /images/web-01.qcow2" >&2
        exit 1
      }
      curl -fL \
        -o /images/ubuntu-24.04-base.img \
        https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img
      qemu-img convert -p -O qcow2 \
        /images/ubuntu-24.04-base.img \
        /images/web-01.qcow2
    HostConfig:
      Binds:
      - /var/lib/nanocl/vm:/images
```

`qemu-img convert` は完全に独立した qcow2 のコピーを作成します。仮想マシンを増やすときは、それぞれ異なる出力ファイル名を使ってください。存在確認により、初期化コンテナの再実行で仮想マシンのディスクが上書きされるのを防ぎます。Nanocl デーモンと仮想マシンのランタイムには、`/var/lib/nanocl/vm` への書き込み権限が必要です。

## 仮想マシンを実行する [#run-a-vm]

簡単なコマンドで仮想マシンを実行できます。

```sh
nanocl vm run web-01 /var/lib/nanocl/vm/web-01.qcow2
```

指定している引数の意味は次のとおりです。

* `web-01` - 仮想マシンの名前。
* `/var/lib/nanocl/vm/web-01.qcow2` - 仮想マシンの書き込み可能なディスクコピーの絶対パス。

オプションを指定しない場合は、次のデフォルト設定で仮想マシンが起動します。

* 1 CPU
* 500 MB の RAM

デフォルト設定での初回起動時間は約 90 秒です。KVM を有効にし、仮想マシンにより多くのリソースを割り当てると短縮できます。

<Callout type="info">

Nanocl はディスクのスナップショットを自動作成しません。仮想マシンにはコピーしたディスクのパスを使い、ダウンロードしたベースイメージは、今後仮想マシンのコピーを作るための元データとしてのみ保持してください。

</Callout>

次のコマンドで仮想マシンに接続し、状態を確認できます。

```sh
nanocl vm attach web-01
```

このコマンドで稼働中の仮想マシンに接続し、コマンドの実行などの操作を行えます。

## 仮想マシンを更新する [#patch-a-vm]

メモリーや CPU などのリソースを変更して、仮想マシンの性能を調整できます。

次のコマンドを使います。

```sh
nanocl vm patch myvm --kvm --cpu 4 --mem 2048
```

上のコマンドで指定しているオプションは次のとおりです。

* `myvm` - 更新する仮想マシンの名前。
* `--kvm` - KVM アクセラレーションを有効にします。
* `--cpu` - 使用する CPU 数を設定します。
* `--mem` - 割り当てるメモリー容量を設定します。

システムで KVM が有効でない場合は、--kvm オプションを省略できます。更新後は、仮想マシンに再接続できます。

<Callout type="warning">

仮想マシンを更新すると、停止して再起動します。

</Callout>

## SSH 接続 [#ssh-connection]

Docker Desktop を使っていない場合は、IP アドレスで仮想マシンに接続できます。仮想マシンの IP アドレスは次のコマンドで取得できます。

```sh
nanocl vm inspect myvm
```

`IPAddress` を取得します。この例では `10.2.0.2` です。
続いて、デフォルトの認証情報 `cloud:cloud` を使って SSH で接続できます。

```sh
ssh cloud@10.2.0.2
```
