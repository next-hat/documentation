Объявляем о выпуске **Nanocl 0.15.0** с новыми возможностями, существенными улучшениями и важными исправлениями для оркестрации контейнеров и управления виртуализацией. Выпуск от **June 11, 2024** приносит долгожданные инструменты и улучшения. Рассмотрим подробности!

{/* truncate */}

## Главное в выпуске [#key-highlights]

### Новые возможности [#new-features]

1. **Улучшенный вывод команд:**
   - Таблицы команд `cargo ls`, `vm ls` и `job ls` теперь показывают состояние ресурсов.

2. **Подробный просмотр:**
   - Новые команды `nanocl metric inspect` и `nanocl event inspect` выводят подробные сведения об отдельных метриках и событиях.

3. **Резервное копирование состояния:**
   - Команда `nanocl backup` сохраняет текущее состояние в нескольких Statefile, позволяя защитить и восстановить конфигурации.

4. **Переопределение переменными окружения:**
   - `HOST` переопределяет хост по умолчанию.
   - `CERT` и `CERT_KEY` передают сертификаты и ключи для клиентских операций.

5. **Удаление осиротевших объектов:**
   - `nanocl state apply --remove-orphans` очищает осиротевшие объекты, поддерживая порядок в среде.

6. **Создание секретов TLS:**
   - `nanocl secret create tls` теперь принимает пути к сертификату и ключу, упрощая создание секретов TLS.

7. **Генерируемые страницы man:**
   - Для всех команд доступны страницы man. Посмотрите их в Markdown [здесь][manpages] или выполните, например, `man nanocl-cargo-create`.


### Исправления ошибок [#bug-fixes]

- **Надёжность команд:**
  - `nanocl cargo run`, `nanocl vm run`, `nanocl cargo start`, `nanocl cargo stop`, `nanocl cargo patch`, `nanocl job start`, `nanocl vm start` и `nanocl vm stop` теперь корректно ожидают завершения соответствующих операций перед возвратом.

- **Сравнение состояний:**
  - При применении Statefile механизм обнаружения изменений теперь точно сравнивает текущее и новое состояние.

### Изменения [#changes]

- **Единый интерфейс:**
  - Команды `inspect`, `rm`, `stop` и `start` приведены к единому интерфейсу для всех объектов.

- **Более компактный вывод:**
  - Из таблиц `cargo ls` и `vm ls` удалено пространство имён.

- **Индикатор загрузки:**
  - Применение и удаление Statefile теперь сопровождается более понятным индикатором загрузки.

# Nanocld 0.15.0

Nanocld 0.15.0, выпущенный **May 16, 2024**, обновляет зависимости, добавляет конечные точки и параметры, а также исправляет несколько критических проблем.

### Основные улучшения [#key-enhancements]

- **Командная строка:**
  - Параметр `--store-addr` позволяет задавать адрес хранилища прямо из командной строки.

- **Новые конечные точки:**
  - `GET /metrics/{key}/inspect` и `GET /event/{key}/inspect` возвращают подробные сведения о метриках и событиях.

- **Репозитории и фильтры:**
  - Новый обобщённый интерфейс `RepositoryCountBy` и улучшенная SQL-фильтрация повышают производительность и гибкость.
  - Индексы добавлены для всех схем SQL, ускоряя запросы.
  - Добавлена фильтрация запросов по датам.

### Исправления ошибок [#bug-fixes-1]

- **Управление заданиями:**
  - Процессы останавливаются перед удалением заданий для корректной очистки.
  - Исправлены проблемы изменения и перезапуска Cargo.

### Изменения [#changes-1]

- **Путь просмотра ресурса:**
  - Путь изменён на `GET /resources/{name}/inspect` для единообразия.

# Ncproxy 0.12.0

Ncproxy 0.12.0, выпущенный вместе с Nanocld **May 16, 2024**, обновляет зависимости и добавляет ограничение запросов для повышения безопасности.

### Основные обновления [#key-updates]

- **Зависимости:**
  - Обновление до ntex версии 2.

- **Ограничение запросов:**
  - Добавлена зона ограничения HTTP-запросов для защиты от злоупотреблений.

### Изменения [#changes-2]

- **Обработка HTTPS:**
  - Перенаправление на HTTPS заменено HSTS (HTTP Strict Transport Security) для повышения безопасности.
