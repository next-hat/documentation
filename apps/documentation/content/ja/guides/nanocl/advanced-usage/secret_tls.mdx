# TLS シークレット

SSL 証明書を追加するには、シークレットを作成する必要があります。<br/>

Nanocl は TLS 証明書、秘密鍵、認証局、DH パラメーターの値を、PEM の内容として CockroachDB に保存します。`ncproxy` は、Nginx がファイルを必要とする場合にのみ、その内容を実行時ディレクトリに書き出します。

## 手動設定 [#manual-setup]

<Callout type="default" emoji="💡">

デプロイ用の `Statefile` から直接シークレットを作成できます。<br/>
ただし、`Secret` の Kind の Statefile を使い、個別に管理することを推奨します。

</Callout>

次の `Statefile` が設定例です。

<StatefileBlock example="advanced/secret-tls" />

CLI でローカルの PEM ファイルを読み込むこともできます。Nanocl はシークレットの作成前にファイルを読み込むため、CockroachDB にはローカルのパスではなく、その内容が保存されます。

<CodeBlock className="language-sh">
{`nanocl secret create tls tls.secret \\
  --certificate-path ./server.crt \\
  --certificate-key-path ./server.key \\
  --certificate-client-path ./ca.crt
`}
</CodeBlock>

<Callout type="info">

Nanocl 0.18 へのアップグレード後の初回起動時に、`nanocld` は旧形式のデータベース TLS シークレットを、読み取り可能なファイルシステムのパスから PEM の内容に変換します。この起動時に古いファイルを読み取れる状態にしておいてください。利用できなくなる場合は、0.17 のデーモンとファイルがまだ利用できる間にシークレットを PEM の内容に更新するか、0.18 を起動する前にファイルを復元してください。

</Callout>

## Let's Encrypt による自動設定 [#automatic-with-lets-encrypt]

[certbot](https://certbot.eff.org/) でドメインの証明書を生成できます。<br/>
この処理を行い、適切な `secret` を作成する汎用の `Statefile` を用意しました。<br/>
シークレットの名前は `cert.{domain_name}` になります。<br/>

<CodeBlock className="language-sh">
{`nanocl state apply -fs nr.next-hat.com/v${nanoclMajorVersion}/certbot -- --email your@email.com --domain deploy-example.com
`}
</CodeBlock>

コマンドが完了すると SSL が有効になりますが、`ProxyRule` を更新する必要があります。<br/>
