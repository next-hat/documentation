# Операции с процессами

Имена Cargo обозначают нагрузки; имена процессов — конкретные контейнеры выполнения. Реплицированный Cargo с несколькими контейнерами имеет несколько процессов. Сначала получите их список:

```sh
nanocl ps --namespace global --kind cargo
```

Имена процессов приложений содержат пространство имён, ключ Cargo, порядковый номер реплики и объявленное имя контейнера. Init-контейнеры, песочницы и временные процессы обновления также различимы в `nanocl ps`. Используйте возвращённое имя или полный Docker ID; не конструируйте имена в скриптах самостоятельно.

Используйте точное значение в командах для отдельных процессов:

```sh
nanocl inspect PROCESS
nanocl logs -f PROCESS
nanocl stats PROCESS
nanocl exec PROCESS -- env
nanocl kill --signal SIGTERM PROCESS
```

`nanocl exec` выбирает один работающий процесс. `--interactive` сохраняет стандартный ввод открытым, `--tty` выделяет псевдо-TTY, а `--detach` запускает команду в фоне. Также доступны повторяемые `--env` и `--env-file`, `--user`, `--workdir`, `--privileged` и `--detach-keys`. В присоединённом режиме без TTY стандартный вывод и ошибки остаются раздельными, а CLI возвращает код завершения выполненной команды.

`nanocl kill` также выбирает один процесс. По умолчанию отправляется `SIGKILL`; для корректного завершения передайте `--signal`. В 0.18 нет `cargo kill` для всего Cargo, а прежняя `cargo exec` удалена.
